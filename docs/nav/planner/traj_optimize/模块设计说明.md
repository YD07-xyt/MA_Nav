## 数据流

1. 输入组装：调用方把上游轨迹转成 `ma_spline_opt::MaSplineInput`，
   起终点会被补齐、按时间排序并去掉时间重复点
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/optimizer_config.h:108-140`），
   同时写入起终速度、加速度与 yaw 角速度
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/optimizer_config.h:142-150`）。
2. 模型分派：按 `ma_spline_opt::OptModel` 走 2D 或 (x,y,yaw) 联合优化
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:165-193`）。
3. 问题构造：用时间点 + 航点 + 边界条件 + 掩码构造问题；**首末航点被 mask 固定**
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:225-231`）。
4. 两阶段优化：同一问题先用 stage1 权重、再用 stage2 权重各跑一次 L-BFGS；
   第二次以第一次的解为初值继续
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:235-244`）。
5. 状态同步：`synchronizeWorkingState` 只用最终决策向量重建输出样条，
   不再重复积分代价与梯度
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/SplineTrajectory/SplineOptimizerProtocols_zh.md:294-298`）。
6. 输出：2D 模式把 xy 样条扩成 (x, y, 0) 的三维样条
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:253`），
   写出时间段、起始时间、代价与成功标志
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:254-257`）。

【事实】每阶段的可选求值入口 `evaluatePrepared` **跳过防御性解码**，
前置条件（上下文有效、决策向量有限）由调用方保证；框架文档明确写了这一点
（`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/SplineTrajectory/SplineOptimizerProtocols_zh.md:294-298`）。

## 线程与并发

【事实】优化器框架内置两种求值执行器：串行的 `SplineTrajectory::SerialExecutor`
与基于 OpenMP 的 `SplineTrajectory::OpenMPExecutor`
（`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/SplineTrajectory/SplineOptimizer.hpp:223-241`），
执行器是求值规格的模板参数，默认是串行版本
（`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/SplineTrajectory/SplineOptimizer.hpp:539-561`）。

【事实】当前生效调用路径**没有启用并行执行器**：门面里没有任何
`withExecutor` 调用，构造求值规格时用的是默认执行器
（`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:301`、`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:382`）。

【待确认】协议文档警告：启用 `SplineTrajectory::OpenMPExecutor` 时，
被借用的积分代价对象必须**线程安全**，因为同一函数对象会被跨段并发调用
（`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/SplineTrajectory/SplineOptimizerProtocols_zh.md:300-311`）。
本模块的 `ma_spline_opt::RobotIntegralCost` 只读自己的配置字段，但是否真的可并发使用
没有代码或文档给出结论。
