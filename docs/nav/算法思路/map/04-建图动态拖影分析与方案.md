## 1. 现状链路

```
/lio/cloud_world ─▶ rog_map 3D log-odds（10×10×4 m 滑窗，0.05 m，射线清除，可选时间遗忘）
                 ─▶ boxSearch(OCCUPIED) ─▶ TerrainAnalyzer（0.1 m，地面=最低点，陡边/间隙判障）
                 ─▶ dynamic_2d_occ_（0.05 m，按 terrain 格真实占地写 1）
                 ─▶ occupancy_2d = dynamic ∪ global ─▶ GridMap + ESDF ─▶ 规划 / save_global_map
```

附带发现【事实】`src/map/src/terrain_analysis.cpp:123` 用 `obstacle_max_z > 0.15f`，比较的是世界系绝对高度，不是相对地面高度。【推算】若地面 z 不为 0，低矮障碍判定会偏。【待确认】是否为有意设计。

### 3D 清除速度【推算】

公式 `ceil((logit(p_max) − logit(p_occ)) / −logit(p_miss))`，p_occ = 0.85。前提：10 Hz，射线每帧都穿过该体素；实际射线不一定每帧穿过，真实时间更长。【待确认】实际点云帧率。

| p_max \ p_miss | 0.49（现） | 0.45 | 0.40 |
|---|---|---|---|
| 0.98（现） | 54 | 11 | 6 |
| 0.95 | 31 | 7 | 3 |
| 0.93 | 22 | 5 | 3 |
| 0.90 | 12 | 3 | 2 |

结论：**<0.5 s 的上限由 3D 决定**。只要 3D 还认为体素占据，2D 层拿不到空闲证据，任何 2D 方案都快不过 3D。要达到 0.5 s，3D 必须落在表中 ≤5 的格子里（降 `p_max` 比降 `p_miss` 对细杆更友好，见 §5）。

## 4. 加减分（A）与比例计数（R）

### 原理

- A：`s = clamp(s + h·[障碍] − f·[空闲], 0, S_max)`，`s ≥ T_in` 进、`s ≤ T_out` 出。状态 = **近期**证据的有界积分。
- R：`hit += [障碍]`，`pass += [障碍或空闲]`，`占据 = pass ≥ N_min && hit/pass > ρ`；超过 `N_cap` 时两者减半。状态 = **历史**证据的比例。

### 对比（【推算】，未实测）

R 的清除次数：站过 k 次（hit = pass = k）后，需要 m 次空闲使 `k/(k+m) ≤ ρ`，即 `m ≥ k·(1/ρ − 1)`。

| 维度 | A 加减分 | R 比例计数 |
|---|---|---|
| 判据含义 | 最近一段时间偏障碍还是偏空闲 | 全部（或最近 N_cap 次）观测里障碍占多少 |
| 清除延迟 | 有界：最多 `(S_max − T_out)/f` 帧，与历史长短无关 | 与历史长度成正比：站过 k 次需约 k·(1/ρ − 1) 次空闲观测 |
| 人站 >5 s 后离开 | 封顶后清除时间固定，可做到 1~3 帧 | 慢：N_cap=40、ρ=0.5 时需约 40 帧（4 s） |
| 原地停时刷票 | 封顶后不再增长，刷票无害 | 不门控会被刷满，必须加关键帧/节流门控 |
| 单帧噪声 | 靠 `T_in` 和滞回抑制；步长越大越敏感 | 天然平滑，`N_min` 挡住少量观测 |
| 细杆间歇漏检 | 漏检帧若产生空闲证据会被快速减掉（f 大时危险） | 比例对间歇漏检不敏感（命中率 50% 仍占据） |
| 静态障碍被挪走 | 同"人离开"，有界快速 | 同"人站很久"，慢 |
| 帧率依赖 | 参数按帧定义，换帧率要重调 | 只看比例，基本无关 |
| 参数 | h, f, S_max, T_in, T_out | N_min, ρ, N_cap, 门控 |
| 存储/计算 | 1 个 int16，逐格加减 | 2 个 uint16，逐格加减 + 一次除法 |

小结：R 擅长"抗噪、抗刷票、细杆稳定"，代价是**清除延迟随历史增长**；A 的清除延迟有界但对漏检敏感。本场景同时要求"站 >5 s 后离开 <0.5 s 消失"和"障碍挪走能更新"，R 的核心短板正好被踩中。

说明：

- 任何纯几何方案都无法在"人站着时"区分人和柱子（【参考】H 的作者在 `DEPLOY.md:68` 写明"总有一些人一直站在那里当静态障碍物"，靠人工清理）。本场景能要求的是"走后快速清除"，这一点 A/W 满足，R 不满足。
- A 的延迟是 **3D 清除 + 2D 计分** 两段串联。3D 已经要 3~5 帧，2D 再加几帧就超过 0.5 s；若把 2D 步长调到 1~2 帧清除，A 就退化成 W 加一点滞回。
- **3D 的 log-odds 本身就是带射线的证据滤波器**。在它后面再串一个 2D 计分器，是重复滤波、多一段延迟。W 把 3D 作为窗口内唯一的事实来源，2D 只负责"窗口外的记忆"。

## 6. 推荐方案：W + 3D 参数调整 + 轻量滞回

### 6.1 2D 三态回写（解决 P1、P2、P3）

- terrain 新增一个输出：本帧"有地面高度、未判障碍"的格（空闲证据）。原 `analyze` 接口和判障逻辑不变，新增重载。
- 建图模式下，`dynamic_2d_occ_` 改为**持久静态图**，每帧只在 terrain 窗口内改写：障碍格写 1，空闲格写 0，无观测格不动。窗口外不动。
- 导航模式行为不变（先验 + 每帧重建）。

### 6.2 3D 参数（解决 P4、P5，决定 <0.5 s）

- 关闭时间遗忘：`forget_threshold ≤ 0`（遮挡静态不再被删）。
- `p_miss` 0.49 → 0.45，`p_max` 0.98 → 0.93：饱和体素 5 帧清除，约 0.5 s。
  - 想更快：`p_max` 0.90 → 3 帧（0.3 s）。`l_max` 等于一次命中，细杆只要隔帧被命中即保持占据。
  - 优先降 `p_max` 而不是继续降 `p_miss`：降 `p_max` 只缩短"饱和后"的清除时间；降 `p_miss` 会让每次擦边射线都对细杆扣更多分。

### 6.3 轻量滞回（防细杆/网格单帧闪断）

- 2D 写 0 需要**连续 2 帧**空闲证据，写 1 立即生效。
- 每格多 1 字节计数，最多增加 1 帧（0.1 s）清除延迟，总延迟仍在 0.5 s 内（配 `p_max` 0.93 为 0.6 s，配 0.90 为 0.4 s）。

### 6.4 保存（解决 P6）

- `save_global_map` 只存持久静态图 ∪ 先验，冻结服务沿用现有实现。站着的人若在保存瞬间在场仍会被存入，这是所有方案共有的限制，靠选时机或保存后人工清理。

### 6.5 预期效果（【推算】，需实测）

| 情况 | 结果 |
|---|---|
| 行人走过 | 在场时占据（可避）；离开后 3D 约 3~5 帧清除，2D 再 ≤2 帧 → ≤0.5~0.7 s |
| 人站 >5 s 后离开 | 同上，3D 已封顶在 `p_max`，延迟不随站立时间增长 |
| 原地停 | 无累计量，不刷票 |
| 被遮挡的墙 | 3D 不遗忘、2D 无观测不写 → 保留 |
| 离开窗口的区域 | 2D 保持离开时的状态 |
| 静态障碍被挪走 | 与"人离开"相同 |
| 细杆/网格 | 3D 需持续命中；2D 滞回挡单帧闪断；风险见 §7 |

## 7. 风险与需实测项

1. **细杆/网格被 3D 射线擦除**（`p_max` 降低后更容易）。需在场地细杆处观察 3D 体素是否闪烁。缓解：射线终点前保留 1 个体素不扣分。【待确认】rog_map 当前 raycast 是否已排除终点体素，本文未核实。
2. **无回波方向不清除**：行人身后是开阔区、超量程时，射线截断点处理为 miss，一般能清；量程内无回波的方向清不掉。
3. **窗口边界**：离开窗口时还未清掉的格会被保留。
4. **地面不可见格**：行人原位置若地面也看不到（NaN），保持旧值。
5. `terrain_analysis.cpp:123` 绝对高度阈值（见 §2 附带发现）。

## 8. 决策与实施（已实现，待实测）

用户确认：`p_max` 可降；窗口内用 3D 当前结果、不单独维护动态层（需保证效果）；2 帧滞回。

实施内容：

- `config/map.yaml`：`forget_threshold` -1（关遗忘），`p_miss` 0.45，`p_max` 0.93。
- `terrain_analysis`：新增 `analyze(robot, occ, free_out)` 重载，输出空闲证据（平坦格，或间隙足够的格）。
  因绝对高度阈值 0.15 m 未判障碍的格不算空闲（保持原值）。旧接口行为不变。
- `ma_map.hpp`：建图模式下障碍格立即写 1；空闲证据需**连续** 2 帧才写 0（中间漏观测则重新计数）；
  无观测和窗口外保持原值。导航模式行为不变。
- 【事实】rog_map raycaster 在终点体素处 `step` 返回 false（`raycaster.cpp:181-183`），终点不扣分，§7.1 已核实。

验证：colcon build 通过；terrain 空闲证据单测与 2D 滞回逻辑模拟通过（临时测试，已删除）。实车/RViz 未验证。

未处理：`save_global_map` 仍用 `occupancy_2d`。建图模式下该值 = 持久图 ∪ 先验，窗口内为当前 3D 结果，因此保存瞬间在场的人会被存入。
§2 的绝对高度阈值未改（见对话说明）。
