## 高风险点与测试点

### R1 terrain 输出语义与头注释不一致（最高优先级）

| 项 | 内容 |
|---|---|
| 头注释声明 | 输出「每个网格中心的点云，z=0 表示可通行，z=1 表示不可通行」 |
| 实现实际行为 | 只输出**障碍点**，且 z 被赋为障碍顶部高度 |
| 证据 | `src/map/include/map/terrain_analysis.hpp:32` 对比 `src/map/src/terrain_analysis.cpp:90`、`src/map/src/terrain_analysis.cpp:125` |
| 调用方假设 | `MaMap` 把返回点**无条件**当作障碍，不检查 z |
| 证据 | `src/map/include/map/ma_map.hpp:85`、`src/map/include/map/ma_map.hpp:91` |
| 为什么危险 | 调用方与头注释的约定是矛盾的。若有人按注释「修正」实现为返回全部格心，`dynamic_2d_occ_` 会被整图置 1，2D 规划栅格直接失效 |
| 测试点 | 【推断】构造一个含可通行区与墙体的点云，断言 `analyze` 返回点数 == 障碍格数（而不是窗口格数）；再断言 `occupancy_2d` 非全 1 |
| 标注 | 【推断】 |

### R2 帧计数与点云快照的并发读写

| 项 | 内容 |
|---|---|
| 现象 | `unfinished_frame_cnt` 不是 `std::atomic`，在锁内自增但在锁外读取 |
| 证据 | `src/map/include/map/ma_map.hpp:169`（声明）、`src/map/include/map/ma_map.hpp:116`（锁内自增）、`src/map/include/map/ma_map.hpp:63`（锁外读取） |
| 为什么危险 | 若 ros2 层把 `update_cloud` 与 `update_map` 放在不同线程/不同 callback group，存在数据竞争，可能丢帧或重复更新 |
| 测试点 | 【推断】用 ThreadSanitizer 跑双线程注入测试；或确认二者在同一 callback group |
| 标注 | 【推断】 |

### R3 里程计超时会静默丢帧

| 项 | 内容 |
|---|---|
| 现象 | `update_cloud` 先检查是否收到里程计，再检查时间差是否超过 `odom_timeout`，任一不满足就 **return 且只打 warn** |
| 证据 | `src/map/include/map/ma_map.hpp:103`、`src/map/include/map/ma_map.hpp:109` |
| 为什么危险 | 代码默认值 0.05 远小于 YAML 值 0.5（见 `配置说明.md`）。若 YAML 缺失该键，点云会被几乎全部丢弃，而地图只是「不动」、不报错 |
| 测试点 | 【推断】在 0.05 与 0.5 两个阈值下分别注入 20 Hz 点云，统计被丢弃帧数；断言 0.5 下丢帧率为 0 |
| 标注 | 【推断】 |

### R4 2D 栅格写入被拒绝时缺少上层反馈

| 项 | 内容 |
|---|---|
| 现象 | `checkMapSize` 尺寸不符时只往 `std::cerr` 打印并返回 false，`setMap` 直接放弃本次更新 |
| 证据 | `src/map/include/map/grid_map.hpp:154` |
| 为什么危险 | 上层拿不到失败信号，规划器会继续用**上一帧**的地图，表现为「地图不更新但不报错」 |
| 测试点 | 【推断】传入行列数不匹配的矩阵，断言 `setMap` 不改变内部缓冲，并断言上层能感知失败（需要新增返回值或日志） |
| 标注 | 【推断】 |
