# 建图模式动态障碍物拖影去除 交接记录

> 状态：主体已实现（commit `f953d87`），有 4 个已知未解决问题，等待后续接手。
> 溯源标记：【事实】读代码确认，后附位置；【推算】由参数计算，未实测；【待确认】需要实测或用户确认。
> 本文只记录"拖影去除"这一条线，不涉及地形分析（限高杆/坡面/台阶）的改造。

## 1. 问题定义

建图模式（`config/planner.yaml: map.mapping_model: true`）下需要边建图边导航，并保存全局地图。
旧实现里 2D 动态层 `dynamic_2d_occ_` 每帧只写 1、从不清零，等于所有帧 terrain 结果的并集：

- 行人、其他机器人走过的地方全部留在 2D 静态图里（拖影）；
- 保存的全局地图带有这些拖影。

因为同时要求"行人离开后 0.5 s 内从 2D 消失"，所以不能简单每帧清零（清零会丢掉滑出 3D 窗口的历史静态地图）。

## 2. 已实现内容

### 2.1 2D 三态回写（建图模式）

位置：`src/map/include/map/ma_map.hpp` `update_map()`

- 障碍格：立即写 1，并清空该格空闲计数。
- 空闲证据：需要**连续 2 帧**才写 0（`kFreeFramesToClear = 2`），中间漏观测则重新计数（`ma_map.hpp:109-120`）。
- 无观测格、滑出窗口的格：保持原值，不清零。
- 导航模式（`mapping_model_ == false`）行为不变：动态层每帧 `setZero()`，静态信息来自先验 `global_2d_occ_`。

### 2.2 terrain 增加空闲证据输出

位置：`src/map/src/terrain_analysis.cpp`、`include/map/terrain_analysis.hpp`

- 新增重载 `analyze(robot_pose, occ_map, free_out)`，额外输出"可以确认是空地面"的格子。
- 旧接口 `analyze(robot_pose, occ_map)` 保留，行为不变（内部转调新重载并丢弃 free_out）。
- 空闲证据的两条来源【事实】：
  - 平坦地面：格内高差 ≤ `max_step_height`；
  - 间隙足够：柱内最大垂直间隙 ≥ `robot_height`（桌下、隧道、限高杆下方）。
- **不输出空闲证据**的情况：间隙不足但由于绝对高度阈值未判障碍的格（判定不明确，宁可保持原值）。

### 2.3 3D 侧参数

位置：`config/map.yaml`

| 参数 | 值 | 说明 |
|---|---|---|
| `forget_threshold` | -1 | 关闭时间遗忘。按"多久没命中"删除会误删被遮挡/盲区的静态障碍（`prob_map.cpp:827-851`）。动态障碍改由射线清除。 |
| `p_hit` | 0.8 | 原 0.9 |
| `p_miss` | 0.45 | 原 0.49，加快射线清除 |
| `p_max` | 0.93 | 原 0.98，压低饱和上限，久站的人离开后清得更快 |

### 2.4 关键数值【推算】

由 `config.hpp:218-223` 取 logit：`l_hit`=1.386、`l_miss`=−0.201、`l_occ`=1.735、`l_max`=2.587。
体素初值 = (l_free + l_occ)/2 = 0.865【事实】`prob_map.cpp:816`。

- **单次命中即占据**：0.865 + 1.386 = 2.252 ≥ 1.735。**注意：当前 `p_hit` 0.8 并不能做到"两次命中才占据"**，要做到需要 `p_hit < 0.705`。
- 单次命中后清除：需 3 次射线 miss。
- 打满 `p_max` 后清除：需 5 次射线 miss（10 Hz 下约 0.5 s，前提是该体素每帧都被射线穿过）。

## 4. 未解决的问题（交接重点）

### 4.1 掠射射线擦掉远处地面【推算，优先级高】

`l_miss` = −0.201，一个体素被一次 miss 就从"未知"变成"已知空闲"。
射向远处地面点的射线贴着地面走，会连续穿过沿途一长串地面体素，每穿一次扣一次分：

- 远处地面在第 1~2 帧内就被擦成 known free；
- terrain 只读 `OCCUPIED`（`ma_map.hpp:212`），地面变成 known free 后 terrain 就看不到地面了；
- 地面缺失又导致地形分析把悬空物、墙当地面，产生 2D 误判。

表现：车开过一段平地后停下，身后 2~4 m 的地面体素消失（RViz `/ma_nav/map/occ` 能看到）。

可选方向：
1. `p_miss` 改回 0.49（单次扣分 0.04 → 需要 22 次 miss 才清）。代价：动态障碍清除变慢，不满足 0.5 s。
2. 射线清除跳过贴近地面的体素（终点附近 N 个，或射线与终点高度差 < 1~2 个体素时不扣分）。代价：改 rog_map 射线代码；贴地的低矮动态物清除稍慢。
3. 地面单独分离存放（见 4.4）。

### 4.2 盲区高处残留清不掉【推算，优先级中】

Mid360 倒装（`odom_robo` roll 3.14），离地约 0.43 m，垂直视场向上只有约 7°。
水平距离 d 处射线能清到的最高高度 ≈ `0.43 + d·tan7°`：0.5 m→0.49 m，2 m→0.68 m，5 m→1.04 m。

- 机器人近处、高于这条线的体素**没有任何射线经过**，拿不到 miss，`p_miss` 调多小都清不掉。
- 表现：人离开后只有离地近的部分消失，高处残留，直到车开远（射线能到更高）或体素滑出 10×10 m 窗口才消失。
- 对 2D 影响可能有限：残留都在 0.43 m 以上，terrain 间隙分析会判"可从下方通过"。但若 `robot_height` 设得接近真实车高，残留会挡住 2D。【待确认】

可选方向：只对"近处 + 视场上沿以上 + 超时未命中"的体素按时间退回未知（不是清成 free）；风险是近处真实的悬空静态物（桌面、横梁）也会被清掉，车离开后重新出现。

### 4.3 单次命中即占据【事实，优先级中】

见 §2.4：`p_hit` 0.8 仍然一次命中就占据。单帧飞点、Livox 边缘混合点、上下坡冲击帧的位姿错位点都会立刻变成占据体素，且因为关闭了遗忘（4.1、4.2）而长期残留。

可选方向：`p_hit` 降到 0.70 以下（两次命中才占据），代价是新障碍晚 1 帧（0.1 s）出现。

### 4.4 结构性方案：地面与障碍分离（未实现）

以上 4.1~4.3 的共同根源是"地面和障碍混在同一张 3D 概率栅格里，并且用同一套射线清除规则"。

设计要点（详细论证见 `docs/nav/算法思路/map/04-建图动态拖影分析与方案.md` 及后续讨论）：

- 每帧先把点云分成地面点和障碍点（区域生长，从机器人脚下开始，允许高差 ≤ 可通行台阶高度）。
- 地面存成 2D 高程图（高度 + 最后观测时间 + 观测距离），不放进 3D 概率栅格，因此不会被射线擦掉；近处观测可覆盖远处观测，纠正 LIO 的 z 漂移；上下坡冲击帧（IMU 角速度/俯仰变化率超阈值）不更新地面。
- 3D 只管障碍，恢复 0.6 s 左右的时间衰减，动态障碍与单帧噪声都会被清掉。
- 2D 写 0 的条件改成"这一格的地面是刚刚（如 0.3 s 内）看到的，且没有障碍"：行人走后地面立刻可见 → 清掉；被挡住的墙其地面也不可见 → 保持，避免误清静态障碍。

代价：新增地面分割与高程图，terrain 的地面来源要改，改动量中等偏大。

## 5. 建议的接手顺序

1. 先在实车/Gazebo 上确认 4.1 与 4.2 的实际严重程度（RViz 里看 `/ma_nav/map/occ` 的地面体素是否在车离开后消失、残留体素的高度）。
2. 只改参数验证 4.1：临时把 `p_miss` 改回 0.49，看远处地面是否变多、2D 误判是否减少。
3. 数值最小的下一步是 4.3（`p_hit` 0.70），能同时缓解飞点与冲击帧。
4. 若要根治 4.1+4.2+4.3，做 4.4。
