## 1 方案概述

重规划模块是规划与控制之间的**编排层**：它决定「这一帧要不要重规划」，
要重规划就串起「搜索 → 优化」，并把结果（两条轨迹 + 状态 + 是否新轨迹）交回节点。

| 项 | 内容 | 锚点 |
|---|---|---|
| 调用方 | 规划定时器（33 ms）→ `plan_omni` → `FsmReplan::plan` | `src/ros2/src/ros2_node.cpp:245-247`、`src/ros2/src/ros2_node.cpp:272` |
| 返回类型 | `tl::expected<ResultPath, PathError>` | `src/planner/replan/include/replan/fsm_replanner.h:81` |
| 结果结构 | 搜索轨迹 + 优化输出 + 状态 + 「是否新轨迹」标志 | `src/planner/replan/include/replan/fsm_replanner.h:66-72` |
| 生效入口 | `plan`（`one_plan` 也是 public，但全仓库无调用点） | `src/planner/replan/include/replan/fsm_replanner.h:83`、`src/planner/replan/include/replan/fsm_replanner.h:90` |
| 状态机 | `SUCCESSED / FAILED / RUNNING / IDLE` | `src/planner/replan/include/replan/fsm_replanner.h:55-60` |
| 实现文件 | 头 141 行 + 实现 292 行 | `src/planner/replan/include/replan/fsm_replanner.h:19`、`src/planner/replan/src/fsm_replanner.cpp:13` |

【事实】本模块**只写 `SUCCESSED`**：`FAILED` / `RUNNING` / `IDLE` 由调用方在节点侧维护
（模块内赋值点只有 `src/planner/replan/src/fsm_replanner.cpp:22` 与
`src/planner/replan/src/fsm_replanner.cpp:107`；节点侧见
`src/ros2/src/ros2_node.cpp:261`、`src/ros2/src/ros2_node.cpp:277`、`src/ros2/src/ros2_node.cpp:292`）。

## 2 核心思想

1. **事件驱动，而不是定时重规划**：只有当「目标变了 / 旧轨迹不再安全 / 车偏离参考线」时才付
   搜索 + 优化的代价；否则复用上一条轨迹
   （`src/planner/replan/src/fsm_replanner.cpp:35-56`）。
2. **用轨迹复检做安全网**：不只是规划时避障，**每次调用都重新检查**上一条优化轨迹
   （以及它的原始栅格路径）在当前地图下是否仍然安全，发现新的动态障碍就立刻重规划
   （`src/planner/replan/src/fsm_replanner.cpp:41-46`、
   `src/planner/replan/src/fsm_replanner.cpp:230-235`）。
3. **宁可外推，不要放弃**：起点/终点贴着障碍时，沿 ESDF 梯度把点推到安全距离再规划，
   避免搜索因为端点落在膨胀层里直接失败
   （`src/planner/replan/src/fsm_replanner.cpp:65-67`、
   `src/planner/replan/src/fsm_replanner.cpp:237-272`）。
4. **到达即收工**：车距目标小于到达半径时直接判成功并清空目标，避免退化路径与周期性空转
   （`src/planner/replan/src/fsm_replanner.cpp:21-25`、
   `src/ros2/src/ros2_node.cpp:257-269`）。
5. **失败如实上报，由调用方决定**：优化失败时直接返回错误，**没有**回退到原始轨迹的兜底
   （`src/planner/replan/src/fsm_replanner.cpp:101-104`；与 `:83` 的注释承诺不一致，见 §6）。
6. **顺带产生折叠计划**：新轨迹下发时按「轨迹 + 地图隧道语义」生成折叠/展开事件，
   交给控制器按跟踪时间消费（`src/ros2/src/ros2_node.cpp:315-321`、
   `src/ros2/src/ros2_node.cpp:197-216`）。

## 3 数学建模（判据的公式化）

### 3.1 记号

| 记号 | 含义 |
|---|---|
| $p_c,\ p_g \in \mathbb{R}^2$ | 当前位姿、目标位姿（取三维状态的 $x,y$ 分量） |
| $\Delta_{g}$ | 目标偏差阈值向量 `goal_deviation`（$[0.2,0.2,0.0]$） |
| $d_{\text{lat}}$ | 横向偏差阈值 `replan_lateral_dev`（0.5 m） |
| $r_{\text{reach}}$ | 到达半径 `goal_reached_radius`（0.3 m） |
| $s_{\text{safe}}$ | 安全阈值 `safe_threshold`（0.35 m，与搜索/后处理同源） |
| $c_{\text{hard}}$ | 硬净空 `hard_clearance`（碰撞复检用的阈值） |
| $P = \{q_0,\dots,q_m\}$ | 参考折线（优化路径的航点序列） |
| $D(\cdot)$ | 地图距离查询（栅格 ESDF 距离） |

### 3.2 到达判定（早退）

$$\|p_c - p_g\|_2 < r_{\text{reach}} \;\Longrightarrow\; \text{置 } SUCCESSED,\ \text{直接返回上一条结果}$$

【事实】模块侧在 `src/planner/replan/src/fsm_replanner.cpp:21-25`，
节点侧还有一层同样的判定并额外清空目标
（`src/ros2/src/ros2_node.cpp:257-269`）。
【推断】两层判定的意义不同：节点侧负责「收工」，
模块侧负责「即使被直接调用也不要产生退化路径」。

### 3.3 三类触发条件

**(a) 目标变化**（逐轴绝对值，不是欧氏距离）：

$$|\Delta p_x| > \Delta_{g,x} \ \lor\ |\Delta p_y| > \Delta_{g,y},
\qquad \Delta p = p_g^{\text{旧}} - p_g^{\text{新}}$$

【事实】比较用的是 `goal_deviation.head<2>()` 的两个分量，第三分量（0.0）不参与
（`src/planner/replan/src/fsm_replanner.cpp:35-39`）。
注意基准是**上一次成功规划时的目标** `old_goal_pose_`
（成功收尾时更新，`src/planner/replan/src/fsm_replanner.cpp:108`）。

**(b) 旧轨迹碰撞复检**：优化路径为空，或复检判定碰撞：

$$\text{collision} \;=\; \big(P_{\text{opt}} = \varnothing\big) \ \lor\ \text{check}(P_{\text{opt}}) \ \lor\ \text{check}(P_{\text{raw}})$$

$$\text{check}(P) = \exists\, q \in \text{densify}(P):\ \text{inMap}(q) \land D(q) < c_{\text{hard}}$$

【事实】原始路径与优化路径**都查**（`src/planner/replan/src/fsm_replanner.cpp:234-235`），
且对每段按 $\lceil \ell/\text{step}\rceil$ 再采样，避免长直线中间漏检
（`src/planner/replan/src/fsm_replanner.cpp:206-221`）；
地图外的点一律视为安全（`src/planner/replan/src/fsm_replanner.cpp:190-197`）。

**(c) 横向偏差**：当前位置到参考折线的最短距离超过阈值：

$$d_{\text{lat}}(p_c, P) = \min_{i=1\dots m}\ \Big\| p_c - \big(q_{i-1} + t_i^\* (q_i - q_{i-1})\big) \Big\|_2,
\qquad t_i^\* = \operatorname{clamp}\!\Big(\tfrac{(p_c-q_{i-1})\cdot(q_i-q_{i-1})}{\|q_i-q_{i-1}\|^2}, 0, 1\Big)$$

【事实】逐段投影并夹紧到线段内（`src/planner/replan/src/fsm_replanner.cpp:163-177`）；
折线点数小于 2 时返回最大浮点数，即**必然触发**重规划
（`src/planner/replan/src/fsm_replanner.cpp:159-161`）。

### 3.4 硬净空与安全阈值的口径差

$$c_{\text{hard}} = \max\big(0.05,\ 0.2 \cdot s_{\text{safe}}\big)$$

【事实】`hard_clearance` 只有这一处定义（`src/planner/replan/src/fsm_replanner.cpp:33`）。
代入当前配置 $s_{\text{safe}} = 0.35$（`config/planner.yaml:24`）得到

$$c_{\text{hard}} = \max(0.05,\ 0.07) = 0.07\ \text{m} \approx 0.2\, s_{\text{safe}}$$

【推断】也就是说：**规划/优化用 0.35 m 的安全距离，而「旧轨迹是否还算安全」只用 0.07 m**——
复检比规划松约 5 倍。这样设计的好处是不会因为轻微贴边就抖动重规划，
代价是从 0.07 到 0.35 之间的贴边状态不会被复检拦住。
模块头文件里还有一个同名注释掉的字段并写明「应 ≤ 通道允许的最小净空」
（`src/planner/replan/include/replan/fsm_replanner.h:29-30`）。

### 3.5 起终点外推（`get_safe_pos`）

对输入点 $p$，若在图外或已满足 $D(p) \ge s_{\text{safe}}$ 则原样返回；否则沿 ESDF 梯度方向迭代：

$$p \leftarrow p + \frac{\nabla D(p)}{\|\nabla D(p)\|} \cdot
\min\Big(\big(s_{\text{safe}} - D(p)\big) + 0.05,\ \ \text{max\_push} - \text{pushed}\Big)$$

终止条件：$D(p) \ge s_{\text{safe}}$、或累计推力 $\ge \text{max\_push} = 1.5$ m、
或步长 $\le 0$、或梯度退化（$\|\nabla D\| < 10^{-6}$）、或迭代到 200 次上限。

【事实】实现见 `src/planner/replan/src/fsm_replanner.cpp:237-272`：
图外直接返回（`:242-244`）、已安全直接返回（`:245-247`）、上限 1.5 m（`:249`）、
200 次（`:251`）、梯度退化 break（`:256-258`）、步长非正 break（`:262-264`）、
达标或到上限提前返回（`:267-269`）。

【推断】加 0.05 m 的余量是为了抵消离散栅格的距离量化误差；
`max_push` 的意义是「不要把起点推得离车太远」，否则轨迹起点会跳。

### 3.6 失败判定：20 秒窗口

节点侧用单调时钟记一个起点，超过 20 s 仍未成功即判失败：

$$t_{\text{now}} - t_{\text{start}} \ge 20\ \text{s} \;\Longrightarrow\; \text{置 } FAILED,\ \text{并重置 } t_{\text{start}} = t_{\text{now}}$$

【事实】判据在 `src/ros2/src/ros2_node.cpp:270-271`，
失败分支在 `src/ros2/src/ros2_node.cpp:273-280`（无路）与
`src/ros2/src/ros2_node.cpp:284-295`（状态非成功）；成功时也会刷新计时起点
（`src/ros2/src/ros2_node.cpp:297`），起点在收到新目标时初始化
（`src/ros2/src/ros2_node.cpp:481`）。
【推断】因为每次超时都把起点刷新为当前时刻，它实际衡量的是
**「连续两次失败之间的间隔」而不是「从开始规划起的累计失败时长」**。

### 3.7 折叠事件生成

**(1) 隧道区间检测**：按固定步长 $\Delta t_s$ 采样轨迹，在时间轴上取「进入 / 离开」地图隧道语义的区间：

$$\text{interval} = \big[\min\{t : \text{isTunnel}(p(t))\},\ \max\{t : \dots\}\big]$$

【事实】按 `local_t` 从 0 到 `duration` 步进（`src/ros2/src/ros2_node.cpp:883-898`），
末段仍在隧道内时以 `duration` 收尾（`src/ros2/src/ros2_node.cpp:900-902`）。

**(2) 区间合并**：间隔太近的两个隧道视为同一段：

$$\text{merge\_gap} = t_{\text{fold}} + t_{\text{unfold}} + 2 m, \qquad
\text{若 } \text{entry}_{i+1} - \text{exit}_i < \text{merge\_gap} \Rightarrow \text{合并}$$

【事实】判据在 `src/ros2/src/ros2_node.cpp:935-945`；
代入 `fold_time = 1.0`、`unfold_time = 1.0`、`fold_margin = 0.5`
（`config/planner.yaml:38-40`）得 $\text{merge\_gap} = 3.0$ s。

**(3) 事件时间**：入口提前、出口延后，起点前需要折叠则强制到 0：

$$t_{\text{fold}} = \max\big(0,\ \text{entry} - t_{\text{fold}} - m\big), \qquad
t_{\text{unfold}} = \text{exit} + m$$

【事实】`src/ros2/src/ros2_node.cpp:950-959`。

**(4) 排序与状态压缩**：按时间排序后，丢弃与前一状态相同的事件，避免连续同状态指令：

$$t_{(1)} \le t_{(2)} \le \dots, \qquad \text{保留 } e_i \iff e_i.\text{fold} \ne e_{i-1}.\text{fold}$$

【事实】`src/ros2/src/ros2_node.cpp:962-973`。

## 4 工程实现

### 4.1 `plan()` 的完整时序

| # | 步骤 | 行为 | 锚点 |
|---|---|---|---|
| 1 | 清标志 | `result_.is_new_trajectory = false`（每次进入先清） | `src/planner/replan/src/fsm_replanner.cpp:18` |
| 2 | 到达早退 | 距目标小于到达半径 → 置成功并返回旧结果 | `src/planner/replan/src/fsm_replanner.cpp:21-25` |
| 3 | 取阈值 | $s_{\text{safe}}$ 来自搜索后处理参数，算出 $c_{\text{hard}}$ | `src/planner/replan/src/fsm_replanner.cpp:32-33` |
| 4 | 三类触发 | 目标偏差 / 碰撞复检 / 横向偏差，任一命中即置 `need_replan_` | `src/planner/replan/src/fsm_replanner.cpp:35-56` |
| 5 | 门控 | **只看 `need_replan_`**：为假则跳过规划直接返回旧结果 | `src/planner/replan/src/fsm_replanner.cpp:58`、`src/planner/replan/src/fsm_replanner.cpp:112` |
| 6 | 准备搜索 | 计时器、注入地图、起终点、起终点外推 | `src/planner/replan/src/fsm_replanner.cpp:59-67` |
| 7 | 搜索 | 强制 JPS、注入速度、调用搜索（超时 5000 ms） | `src/planner/replan/src/fsm_replanner.cpp:69-74` |
| 8 | 优化 | 构造地图适配器 → 注入指针 → **固定 2D 模型** → 优化 | `src/planner/replan/src/fsm_replanner.cpp:92-100` |
| 9 | 成功收尾 | 保存优化输出、置新轨迹标志与成功状态、记录旧目标、清标志 | `src/planner/replan/src/fsm_replanner.cpp:105-110` |
| 10 | 失败 | 搜索失败 → `PLANNING_FAILED`；优化失败 → `MINCO_OPT_FIALED` | `src/planner/replan/src/fsm_replanner.cpp:76-80`、`src/planner/replan/src/fsm_replanner.cpp:101-104` |

【事实】第 5 步的 `need_replan_` **初值为真**（`src/planner/replan/include/replan/fsm_replanner.h:63`），
且规划失败后仍置真（`src/planner/replan/src/fsm_replanner.cpp:78`），
只有成功收尾才清假（`src/planner/replan/src/fsm_replanner.cpp:109`）。
因此「三类条件都不成立」**并不等于**「不会重规划」——标志残留（首次调用、上次失败）同样会进入重规划分支。

### 4.3 与折叠下发的接口

新轨迹生效时会把跟踪游标定位到新轨迹上离车最近的时间
（`src/ros2/src/ros2_node.cpp:339-344`，用 `nearest_time`），
并跳过新轨迹上已经过去的折叠事件、把「当前应有状态」写进记账变量
（`src/ros2/src/ros2_node.cpp:323-338`）。

【事实】这一步**只更新记账变量**：真正补发折叠指令的那行被注释
（`src/ros2/src/ros2_node.cpp:336`），因此「应有状态」与实际下发过的状态可能静默发散；
实际下发由控制回调按到期事件完成（`src/ros2/src/ros2_node.cpp:197-216`）。【待确认】这行注释是临时调试残留还是有意取消补发，代码与注释都没有说明。

### 4.5 失败分支与错误码

| 场景 | 返回 | 调用方行为 | 锚点 |
|---|---|---|---|
| 搜索无路 | `PLANNING_FAILED`，并再置 `need_replan_ = true` | 静默重试；20 s 后判失败 | `src/planner/replan/src/fsm_replanner.cpp:76-80` |
| 优化失败 | `MINCO_OPT_FIALED`（**无兜底**） | 同上 | `src/planner/replan/src/fsm_replanner.cpp:101-104` |
| 到达 | 返回旧结果 + `SUCCESSED` | 清空目标收工 | `src/planner/replan/src/fsm_replanner.cpp:21-25` |
| `MAX_RETRIES` | 枚举存在但**从未被返回** | — | `src/planner/replan/include/replan/fsm_replanner.h:79` |

【事实】注释在 `src/planner/replan/src/fsm_replanner.cpp:83` 承诺

而实现直接返回错误（`:101-104`），调用方丢弃该结果且不发布轨迹
（`src/ros2/src/ros2_node.cpp:273-279`）。

## 6 已知限制与优化方向

| # | 限制 | 影响 | 优化方向 |
|---|---|---|---|
| 1 | **优化失败没有兜底** | 注释承诺退回原始轨迹，实现直接报错；调用方不发布，底盘继续执行上一帧指令 | 二选一：实现「退回 `planning_traj`」或删除误导性注释并明确失败语义 |
| 2 | `need_replan_` 标志残留 | 「三条件都不成立」也会重规划；失败后每帧都重试，没有退避 | 明确「首帧必须规划」的语义（初值即可），失败路径引入退避/最小间隔 |
| 3 | 20 s 语义是「两次失败的间隔」 | 每次超时都重置计时 ⇒ 长期失败不会累积到失败判定以外的作用 | 若想要「总失败时长」，不要在超时分支重置起点。【待确认】该语义是否有意为之，注释未说明 |
| 4 | `last_opt_path_` 从未赋值 | 横向偏差恒以最新结果为准；「优先用上次路径」的分支不可达 | 删除该成员，或在下发新轨迹时赋值 |
| 5 | 参数缺默认值、热启动参数未接线 | 缺 YAML 键 → 阈值/半径读到不确定值；有效期/连续性阈值/投影分辨率读入后无人使用 | 头文件给默认值（缺键报错），并接入或删除未接线参数（连同 `min_replan_interval`） |
| 7 | 折叠状态可能发散 | 新轨迹的「应有状态」只写记账变量，补发指令被注释 | 恢复补发，或改为「以下一帧事件为准」并同步记账 |
| 8 | 隧道检测采样 0.002 s | 每 1 s 轨迹约 500 次地图语义查询，长轨迹成本可观 | 用声明的 0.02 s 默认值，或按速度自适应 |
| 9 | 死代码与陈旧判据 | `one_plan`、`check_point_equal`、投影结构、两个成员、一个枚举值无使用者；代码注释写明「暂不考虑加入路径年龄」 | 一次性清理或标注保留原因；长直线场景可加路径年龄触发 |
| 10 | 构造入口不对称 | 用带参构造时优化器拿不到配置 | 统一走 `set_param`，或在带参构造里补齐分发 |
| 11 | 硬净空比安全阈值松 5 倍 | 0.07 m 到 0.35 m 的贴边状态不会被复检拦住 | 按通道最小净空重新标定该系数 |

【推断】第 1、2、7 条是**相互关联**的：因为优化失败没有兜底、标志又残留，
系统在极端场景下会持续以 33 ms 的节拍重复「搜索 + 优化」直到 20 s 判失败；
在实现兜底与退避之前，这类场景的 CPU 占用值得实测。
