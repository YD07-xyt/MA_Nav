# 地形分析：台阶边沿闭合 + 悬空净空判据稳定化 改造记录

## User Intent

实车/仿真测试上一版（`20261020_terrain_multilayer_patch.md`）后反馈两个问题：

1. **矮台阶无法完全看成障碍物**：20 cm 台阶（爬不上去）在 2D 里只被零星挡住，边沿没有完全闭合。
2. **限高杆会有 2D 障碍物跳变**：限高杆横梁区域的白块会按帧闪/跳。

约束（沿用前序讨论）：
- 机器人真实最高点 < 250 mm，能爬的最大台阶 < 10 cm。
- 限高杆净空实测约 250 mm，要求整段可通行（含跨坡段）。
- 高台策略保"甲"：台阶/高台边沿一圈判障碍，高台内部、坡道可通行。
- 2D 里"未知"不写障碍。
- 不能破坏比赛验证过的主逻辑；最小改动；不改接口、不改 2D 回写、不新增配置项。

### Root cause

**问题 1（矮台阶不闭合）**，三条叠加：

a. **灰区吞掉了 20 cm 台阶**。上一版"悬空片下沿 ∈ [0.12, robot_height) → 不下结论"。而 20 cm 台阶的台面/立面在参考地面之上正好 0.20 m，落在灰区里 → 既不写障碍也不写空闲，2D 保持原值（多为空闲）→ 台阶"看了个寂寞"。这是主因。
b. **边沿只靠"立面柱"一种来源**。台阶边沿的竖直面投影到 0.05 m 栅格上只有 1 格宽，LiDAR 掠射时这一格常常无点（`list.empty()` → 未知不写）→ 边沿出现断口。
c. **地面参考窗口太小**：`kernel_size=3` 在 0.05 m 分辨率下只有 15 cm，3x3 里低处地面最多占 3/9，25% 分位仍取到台面高度 → 台面边沿不会被判成"相对低地抬高"，第 b 条的断口无法从台面一侧补上。

**问题 2（限高杆跳变）**，两条叠加：

a. **判据对同一格有两套数学**：柱子同时有地面片和横梁片时走旧判据 a，`max_gap` 从**地面片顶**起算 —— 地面片厚度（1~3 cm 噪声）被折进净空，得到 0.22~0.24；柱子只有横梁片时走旧判据 b，净空从**参考地面**起算，得到 0.25。同一根梁上"这一帧有没有采到梁下地面点"逐帧变化 → 同一格在两套判据/两个数值之间跳。
b. **净空 250 mm 与门限 240 mm 只差 1 cm**，逐格单帧的净空估计抖动（每格点少、取最低点偏低）就有几厘米 → 直接门限化必然翻转。翻转后"障碍立即写 1、空闲要连续 2 帧且帧号相邻才清"，表现为白块闪现/跳变。

### Recommended modification boundary

只改 `terrain_analysis.cpp` 的判定部分 + `map.yaml` 注释；接口、2D 回写、参数值不变。

## Modifier Changes

### Files changed

- `src/map/src/terrain_analysis.cpp`
- `config/map.yaml`（仅注释）

### Key changes

1. **删掉灰区**：悬空结构只有一条门限——"柱内最低悬空片下沿离参考地面 < `robot_height` → 障碍，否则可通行"。20 cm 台阶台面（0.20 < 0.24）因此被稳定挡住，不再"不写"。
2. **净空改为从参考地面起算**：`clearance = 最低悬空片.bottom - z_ground`，不再像旧判据 a 从地面片顶起算，去掉地面片厚度对净空的系统性侵蚀（这是限高杆"擦线翻转"的直接原因）。
3. **净空邻域聚合后再门限**：`clearance_agg` = 5x5 邻域内"同一结构层"（净空与自身相差 ≤ `kClearanceBand` 0.10）的柱的 **75% 分位**。
   - 压掉单帧逐格抖动（一个结构在邻域内有多个同类柱）；
   - 高分位补偿"每格取最低点"的偏低估计；
   - 只聚合相近净空，避免台阶旁的更高台面/悬挂物把台沿净空抬高。
4. **竖直结构判据改用"贴地片"本身的高度**：`grounded && (最低片.top - 地面) >= kVerticalStructureHeight`。旧版用整柱最高点，会把"矮台 + 高处悬挂物"的柱当成从地面升起的墙。
5. **横向连续性判据**（细杆/稀疏立柱保护，保留上一版语义）：
   - 窗口 3x3 → 5x5（更抗单帧漏采）；
   - 判据从"片底相差 ≤ 0.08"改成**片区间相交**（`q.bottom ≤ p.top+tol && q.top ≥ p.bottom-tol`），因为同一结构有的格只采到顶面、有的只采到底面。
6. **新增"表面高差"判据 c**：本柱可落脚面（贴地薄片顶）比半径 2 格内某邻柱可落脚面**低 10 cm 以上**，且至少 2 个这样的"干净低处"见证 → 障碍。
   - 这条不依赖"这一格采到立面点"，所以立面条无点时边沿也能从台面一侧闭合，把 20 cm 台阶的边沿做成连续一圈；
   - 只标高处一侧，低处不跟着变白；
   - "干净"= 见证格上方留得出可通行净空，否则只是台阶边混了低处杂点的柱，拿它当见证会把台面里也拉白；
   - 低处见证数下限 2，抑制单点噪声。
7. **未知语义不变**：无任何片的柱、或其 3x3 邻域没有可靠地面参考的柱，仍然什么都不写（2D 保持原值）。
8. **删除已无用的常量** `kOverheadBlockMax`（灰区下界），新增 `kClearanceRadius/Quantile/Band`、`kOverheadSupportRadius`、`kMaxClimb`、`kStepSearchRadius/WitnessMin`，全部为函数内 `static constexpr`。

### Behavior preserved

- `analyze` 两个重载签名、返回值语义、`free_out` 语义不变。
- 2D 三态回写、空闲 2 帧滞回、建图/导航分支、拖影逻辑不变。
- 平地、11°/15° 坡面：可通行（离线验证 0 误判）。
- 限高杆/隧道顶/桌下（净空 ≥ robot_height）：可通行；细杆/稀疏立柱仍判障碍。
- 20 cm 台阶立面本身：仍判障碍。
- 高台内部可通行（甲），且高台/台阶边沿一圈障碍。
- `robot_height`、`kernel_size`、`config_.max_step_height` 等的值与语义不动。

### Behavior intentionally adjusted

- **灰区消失**：上一版"悬空片下沿 0.12~robot_height 不下结论"的格现在明确判障碍。20 cm 台阶台面/立面靠这条从"不写"变成"挡"。
- **台阶/台沿内侧多一圈**：新增判据 c 会在台阶高处一侧标一圈（约 1~2 格 = 5~10 cm），低处侧不标。这是"边沿闭合"的代价，也是甲策略要的"一圈障碍"。
- **限高杆段从"擦线"变成"留有余量"**：净空不再被地面片厚度吃掉，聚合后整段一致 pass。
- **竖直结构判据变严于"薄片"、宽于"整柱最高点"**：矮台 + 高处悬挂物不再误判为墙。

### Notes

- 新阈值：`kClearanceRadius` 2、`kClearanceQuantile` 0.75、`kClearanceBand` 0.10、`kOverheadSupportRadius` 2、`kMaxClimb` 0.10、`kStepSearchRadius` 2、`kStepWitnessMin` 2。调参优先动 `kMaxClimb`（台阶灵敏度）、`kStepWitnessMin`（边沿厚度/抗噪）、`kClearanceQuantile`（限高杆放行余量）。
- 每帧新增开销：一次 5x5 净空聚合 + 每格 5x5 支撑/见证检查（带提前退出），仍是 O(格数) 量级。

## Known issues / 风险

1. **台阶立面条 1 格抖动**：立面本身采样到就白、没采到就空，2D 上表现为台阶边沿最外一格 5 cm 闪。边沿一圈由判据 c 从台面侧闭合，所以"是否漏路"不受影响，但观感上最外一格仍会闪。若现场明显，可把判据 c 的 `kStepWitnessMin` 降到 1（更保守，但抗噪变差）。
2. **稀疏立柱/细杆偶发误放行**：立柱点若被拆散到多个格、且某格只采到高处点，会走"悬空 + 横向连续"路径被放行。真实立柱点密，逐格基本能形成贴地厚片（判据 a），合成点云里的翻转是采样碎片化放大。若现场出现，可减小 `kOverheadSupportRadius`。
3. **限高杆净空余量**：门限仍是 `robot_height` 0.24，实测净空 250 mm 只有 1 cm 余量。聚合后稳定，但若现场测得净空 < 240 mm，需要按实测调 `robot_height`（这是唯一有权改这个值的场景）。
4. **高台边沿内侧 1~2 格变白**：判据 c 的半径 2 决定，属甲策略的"一圈"，会略微缩小台面可用区域。
