## 数据流

1. **入口与早退**：清「新轨迹」标志；若当前位姿距目标小于到达半径，直接置成功并返回
   （`src/planner/replan/src/fsm_replanner.cpp:18-25`）。
2. **阈值准备**：安全距离取自 path_planning 参数；
   硬净空取「安全距离的 20%，且不低于 0.05 m」
   （`src/planner/replan/src/fsm_replanner.cpp:32-33`）。
3. **触发判定**：目标变化 → 旧轨迹碰撞（同时查优化航点与原始栅格路径）→
   横向偏差（当前点到折线的最短距离）
   （`src/planner/replan/src/fsm_replanner.cpp:35-56`）。
4. **重规划分支**：计时 → 注入地图 → 起终点安全外推 → JPS 搜索
   （`src/planner/replan/src/fsm_replanner.cpp:58-74`）。
5. **优化分支**：把搜索结果转成优化输入 → 设 2D 模型 → MINCO 优化
   （`src/planner/replan/src/fsm_replanner.cpp:92-104`）。
6. **成功收尾**：保存两条轨迹、置新轨迹标志与成功状态、记录本次目标、清重规划标志
   （`src/planner/replan/src/fsm_replanner.cpp:105-110`）。
7. **未触发分支**：原样返回上一次的结果结构
   （`src/planner/replan/src/fsm_replanner.cpp:112`）。

【事实】第 5 步的 MINCO 输入来自**搜索后处理轨迹**而不是优化后的轨迹
（`src/planner/replan/src/fsm_replanner.cpp:94`），
两者使用的是同一个 `trajectory` 值。

## 关键设计决策

| 决策 | 证据锚点 | 是否代码明示 |

| 目标变化用逐轴绝对差与阈值比较 | `src/planner/replan/src/fsm_replanner.cpp:37` | 是 |

| 折线段按步长再采样，避免长直线漏检 | `src/planner/replan/src/fsm_replanner.cpp:206-217` | 是 |
| 安全外推有上限（1.5 m、200 次迭代） | `src/planner/replan/src/fsm_replanner.cpp:249-251` | 是 |

| 每次重规划都新建地图适配器并重新注入优化器 | `src/planner/replan/src/fsm_replanner.cpp:92-93` | 【推断】（避免持有跨帧的地图指针，但留下了顺序依赖） |
| 计时对象开启打印（`planner_fsm`） | `src/planner/replan/src/fsm_replanner.cpp:59` | 是 |

【推断】决策「每次重规划都重新注入 ESDF」的动机是生命周期安全：
适配器是函数内局部对象，优化器只保存裸指针，
因此同一个函数内「先注入、后使用」可以避免悬垂（依据：
`src/planner/replan/src/fsm_replanner.cpp:92-100`）。
代价是这条顺序要求没有类型保护，见风险 4。

## 线程与并发

【事实】本模块没有任何互斥量、原子量或线程设施
（`src/planner/replan/include/replan/fsm_replanner.h:2-17` 的 include 列表里没有线程相关头）。

【推断】门面**非线程安全**且**有跨帧状态**：
`replan::FsmReplan::result_`、`replan::FsmReplan::need_replan_`、
`replan::FsmReplan::path_state_`、`replan::FsmReplan::old_goal_pose_` 都会跨调用保留
（`src/planner/replan/include/replan/fsm_replanner.h:62-73`），
因此同一个实例不能被并发调用；当前调用方是单线程逐帧调用
（`src/ros2/src/ros2_node.cpp:272`）。
