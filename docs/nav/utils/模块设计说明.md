## 数据流

1. **日志数据流**：业务代码 → `logger::info` 等结构体（构造参数含 `std::source_location`）
   → spdlog 通道 → stdout 彩色输出（`src/utils/include/utils/logger.hpp:19-24`）。
2. **计时机理**：栈上创建 `utils::TimeConsuming` → 析构时计算耗时并按量级换算
   → 写入计时通道（`src/utils/include/utils/scope_timer.hpp:62-79`）。
3. **参数装载**：业务构造 → `yaml_loader::YamlLoader` → 每次装载都重新读取 YAML 文件
   → 命中则取值、类型不符或缺失则回落默认值（可选抛异常）
   （`src/utils/include/utils/yaml_loader.hpp:48-104`）。
4. **类型传播**：`utils::decimal_t` = double，所有别名基于它
   （`src/utils/include/utils/eigen_alias.hpp:22`），因此改一处即可切换全局精度。
5. **算法单头**：`lbfgs.hpp` 由 traj_optimize 直接调用
   （`src/planner/traj_optimize/include/traj_optimize/ma_spline_opt/traj_optimizer.h:8`）；
   `expected.hpp` 由 traj_optimize 与 replan 用作返回值类型
   （`src/planner/replan/include/replan/fsm_replanner.h:9`）。

## 线程与并发

【事实】本模块本身几乎没有共享可变状态：

| 组件 | 并发性质 | 锚点 |
|---|---|---|
| 日志 | 由 spdlog 保证线程安全，且通道是头文件内 inline 变量（进程内一份） | `src/utils/include/utils/logger.hpp:101-125` |
| 计时器 | 每个实例是栈对象，只被创建它的线程使用 | `src/utils/include/utils/scope_timer.hpp:39` |
| 参数装载 | 每次调用都重新读文件，没有跨调用缓存 | `src/utils/include/utils/yaml_loader.hpp:49` |
| 绘图器 | 自带互斥锁保护发送（当前无调用点） | `src/utils/include/utils/plotter.hpp:36` |
| 枚举与别名 | 纯类型定义，无状态 | `src/utils/include/utils/type_utils.hpp:17` |

【推断】因此本模块不会成为数据竞争源；风险集中在**依赖可见性**（见下）而不是并发。
