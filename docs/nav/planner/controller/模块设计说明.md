## 数据流

1. **构造期**（只做一次）：由参数离散化模型
   （`src/planner/controller/include/controller/mpc.h:120-133`），
   再一次性构建常数 Hessian 与常数线性约束矩阵并初始化 OSQP
   （`src/planner/controller/include/controller/mpc.h:148-292`）。
2. **每帧输入**：状态 `x0`、当前时间 `t_now`
   （`src/planner/controller/include/controller/mpc.h:400-406`）。
3. **采样参考**：从轨迹接口取 `N+1` 个参考点
   （`src/planner/controller/include/controller/mpc.h:311-316`）。
4. **更新梯度**：由参考状态/控制生成线性项
   （`src/planner/controller/include/controller/mpc.h:321-334`）。
5. **更新边界**：初始状态等式、动力学等式（右侧为 0）、vx/vy 与控制量区间
   （`src/planner/controller/include/controller/mpc.h:339-380`）。
6. **求解与提取**：`updateGradient` / `updateBounds` → `solveProblem` → 取解，
   当前控制量是决策向量中第一段控制
   （`src/planner/controller/include/controller/mpc.h:450-490`）。
7. **输出**：当前控制量 + 预测状态序列 + 预测控制序列，
   并保存本次控制量
   （`src/planner/controller/include/controller/mpc.h:493-525`）。

## 关键设计决策

| 决策 | 证据锚点 | 是否代码明示 |
|---|---|---|
| Hessian 与约束矩阵是常数，每帧只更新梯度与边界 | `src/planner/controller/include/controller/mpc.h:173-215` | 是（注释写明「常数」） |
| 打开 OSQP 热启动、关闭冗余输出 | `src/planner/controller/include/controller/mpc.h:279-280` | 是 |
| Hessian 只取权重矩阵的对角线，线性项却用整矩阵 | `src/planner/controller/include/controller/mpc.h:185`、`src/planner/controller/include/controller/mpc.h:327` | 是（两处实现不一致，见风险 1） |
| 控制增量惩罚只作用于同一次求解内的相邻控制 | `src/planner/controller/include/controller/mpc.h:197-207` | 是 |
| 状态硬约束只覆盖速度分量，且从 k=1 开始 | `src/planner/controller/include/controller/mpc.h:250-262` | 是（注释写明「只约束 vx,vy」） |
| 参考点超出行驶时长时被钳制在终点 | `src/planner/controller/include/controller/traj_interface.hpp:79` | 是（`std::clamp`） |
| 跟踪时间用局部窗口搜索、最近时间用全时长粗扫 | `src/planner/controller/include/controller/traj_interface.hpp:96` | 【推断】（两种粒度并存，注释未说明取舍） |
| 轨迹以**值**保存上游输出（每次下发都拷贝一次样条） | `src/planner/controller/include/controller/traj_interface.hpp:137` | 是 |

【推断】决策「Hessian 常数」的动机是效率：QP 结构只与参数有关，
每帧变化的只有参考轨迹带来的线性项和状态带来的边界，因此可以复用 OSQP 的
符号分解与热启动（依据：`src/planner/controller/include/controller/mpc.h:95-96`）。

## 线程与并发

【事实】本模块没有任何互斥量、原子量或线程设施，
include 列表只有 Eigen、OsqpEigen、自身接口头与 STL
（`src/planner/controller/include/controller/mpc.h:3-8`）。

【推断】控制器**非线程安全**：OSQP 求解器实例与 QP 数据都是成员状态，
求解还会写回 `control::Mpc::param_`（`src/planner/controller/include/controller/mpc.h:525`），
因此同一个 `control::Mpc` 实例不能被并发调用。当前调用方是单线程逐帧调用
（`src/ros2/src/ros2_node.cpp:179`）。

## 已知限制与风险

| # | 限制 / 风险 | 说明 | 锚点 | 类型 |
