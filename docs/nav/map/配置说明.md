# map 模块 配置说明

> 本文所有「YAML 值」来自 `docs/_evidence/repo/params.json` 的**解析值**，
> 不是注释文本。代码默认值来自 `LoadParam` 的第三个实参。

## 参数读取机制

`map` 模块**不使用** `config["a"]["b"]` 键链，而是用 utils 模块提供的
`LoadParam`，路径是**斜杠分隔的字符串**，
并带一个命名空间前缀。

| 项 | 内容 | 锚点 |
|---|---|---|
| YAML 文件 | `/home/xyt/map/src/MA_Nav/config/map.yaml`（由 planner.yaml 指定） | `config/planner.yaml:10` |
| 传递链 | ros2 节点读 `ros2.map_params_path` 后传给 `MaMap` | `src/ros2/src/ros2_node.cpp:33` |
| 构造点 | `MaMap` 构造时创建 `rog_map::Config(cfg_path)` | `src/map/include/map/ma_map.hpp:16` |
| 读取器 | `rog_map::Config` 构造体内创建 `YamlLoader` | `src/map/include/map/3d_occ_map/config.hpp:68` |
| 命名空间前缀 | `name_space` 默认 `"rog_map"`，与 map.yaml 顶层键一致 | `src/map/include/map/3d_occ_map/config.hpp:67` |
| LoadParam 声明 | 标量/向量两个重载 | `src/utils/include/utils/yaml_loader.hpp:39` |
| 参数边界计算 | 读取完成后统一调用 `resetMapSize()` | `src/map/include/map/3d_occ_map/config.hpp:214` |
| map.yaml 顶层 | `rog_map:` | `config/map.yaml:1` |

因此 `LoadParam(name_space + "/resolution", ...)` 实际读取的键路径是
`rog_map.resolution`。**把前缀漏掉会写成错误的键路径**，
这是本模块配置文档最容易出错的地方。

## 代码读取但 YAML 未定义的键

对应 `params.json` 的 `unresolved_paths`（map 模块部分共 4 条）。
这 4 个键在 `config/map.yaml` 中不存在，读取会**退回到代码默认值**。

| # | 键路径 | 代码默认值 | 读取行号 | 后果 |
|---|---|---|---|---|
| 1 | rog_map.pcd_name | "map.pcd" | 97 | 仅在 `rog_map.load_pcd_en` 为 true 时读取；当前 YAML 未定义 |
| 2 | rog_map.visualization.use_dynamic_reconfigure | false | 120 | 动态调参开关无法从 YAML 配置 |
| 3 | rog_map.visualization.frame_id | 代码默认值 | 122 | 可视化坐标系无法从 YAML 配置 |
| 4 | rog_map.visualization.frame_rate | 代码默认值 | 124 | 可视化帧率无法从 YAML 配置 |

【待确认】这 4 项是有意留用代码默认值，还是 map.yaml 漏配？需要作者确认，
见 `待确认清单.md`。

## YAML 定义但代码未引用的键

【事实】`config/map.yaml` 的**全部**键都能在代码中找到读取点
（校验依据：`params.json` 中 `unread_keys` 不含 `config/map.yaml` 的任何键）。

`params.json` 中剩余的 28 条「未被提及键」全部位于 `config/planner.yaml`，
属于 planner 模块的参数范围，不在本文档范围内。同时还有 112 条
`subnode_reads`（作用在 yaml-cpp **局部子节点**上的读取，例如
`node["rho_energy"]`），需要用跨函数的调用点推导才能确定绝对键路径，
本次未实现，列入 `待确认清单.md`。
