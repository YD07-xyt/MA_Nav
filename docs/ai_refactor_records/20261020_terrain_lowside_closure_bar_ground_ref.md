# 地形分析：宽窗地面参考 + 台面一侧不再判障碍 + 台阶低侧闭环 改造记录

> 本记录取代 `20261020_terrain_step_edge_closure.md` 中"表面高差判据 c（只标高处一侧）"部分。
> 上一版判据在下述三点上仍不满足现场要求，本版重写判定段。

## User Intent

实车测试上一版（`20261020_terrain_step_edge_closure.md`）后用户反馈三个问题：

1. **限高杆下地面点少时无法过滤限高杆**（2D 白块落在梁上）。
2. **台阶处台面一侧点少时，台阶无法被判成障碍物**。用户提问：在低地是否可以把低台阶判成障碍物，
   不依赖台面一侧的点。
3. **台阶处台面一侧的点容易被判成障碍物**（低台阶被当障碍时，台面一侧也被吃进去/白块抖）。

约束（沿用前序讨论）：
- 机器人真实最高点 < 250 mm，可攀爬最大台阶 < 10 cm；限高杆实测净空约 250 mm，要求整段可通行。
- 2D 里"未知"不写障碍；高台内部、坡道、坡道↔台面接缝必须可通行；台阶/台沿边沿必须闭合。
- 不破坏比赛验证过的主逻辑；最小改动；不改接口、不改 2D 回写、不新增配置项。

### Active logic path

`/lio/cloud_world` → rog_map 3D 概率栅格（0.05 m 体素）→ `boxSearch(OCCUPIED)`（体素中心点）→
`TerrainAnalyzer::analyze` → `terrain_map_`（障碍）/ `terrain_free_`（空闲证据）→
2D 三态回写（障碍立即写 1；空闲需连续 2 帧且帧号相邻才写 0）→ `occupancy_2d` → `GridMap::setMap` → ESDF/JPS。

关键事实：**terrain 的输入是 0.05 m 体素中心点**，同一竖直结构在点云里表现为离散层（层中心 0.025+0.05n），
"薄片"判定会把台面/横梁这类单层结构当成薄片。上一版没有考虑这一点。

### Root cause

**问题 1（限高杆下地面点少时过滤不了）**

地面参考 `ground_cand` 只要求"柱内最低片是薄片"，而横梁本身也是"薄的最低片"：
横梁下方没有地面点时，该柱的地面候选 = 横梁标高。上一版地面参考窗是 `kernel_size=3`
（0.05 分辨率下 ±0.075 m），小于横梁宽度（仿真里 0.2~0.25 m）时，3×3 窗口内全是横梁自己的候选
→ `z_ground` 被抬到横梁标高 → 横梁被当成"贴地"的台面 → 触发"表面高差"判据 c 判障碍并逐帧翻转。
地面对称地少一点，就会有一批柱的 3×3 窗口被横梁占满 → 就是现场看到的"横梁一段白、还闪"。

**问题 2（台面一侧点少时边沿漏检）**

上一版判据 c 只从**台面一侧**标障碍，且要求台面一侧自己满足 `surface`（薄贴地片 + 3×3 窄窗地面参考）。
体素化输入下，台面/立面的单层薄片会把窄窗地面参考拉到台面层，`surface` 不稳定；
台面一侧采样少时 surface 缺失 → 边沿没有障碍，只能靠立面柱（1 格）兜底 → 边沿出现断口。
低地一侧没有任何"看到台阶就要判障碍"的判据。

**问题 3（台面一侧被误判）**

- 判据 c 把"可落脚面比邻域低处高 >10cm"的格直接判障碍，且标的是**高处一侧**；
  20 cm 台面在窄窗下常被当成"相对低地抬高 20cm 的台面格"→ 台面一侧被吃进 1~2 格。
- 判据 b 对净空 < robot_height 的抬高片一律判障碍：20 cm 台阶台面（0.20 < 0.24）整个边缘带被挡住，
  而台面顶面本身是机器人可以行驶的区域（高台从坡道上去后要开）。
- 台面一侧采样稀疏时，这些判定逐帧抖动 → 白带破碎。

**共性根因**：3×3 窄窗 + 0.25 分位的地面参考，在体素化输入下无法区分"地面"和"单层薄片结构"；
且台阶边沿的判定只从台面一侧做。修复方向：宽窗低分位地面参考（抗结构污染）+ 抬高面/台面区分 +
台阶边沿只从低处一侧闭环。

## Modifier Changes

### Files changed

### Key changes

1. **地面参考改为宽窗低分位**（`terrain_analysis.cpp:165`）：
   `z_ground = quantileFilter(ground_cand, kernel_size, 0.10)`，`kernel_size` 3→7（±0.175 m）。
   宽窗保证窗口一定大于限高杆横梁进深，低分位保证从邻域地面取值而不是被抬高结构抬高。
   `kGroundedTol` 由 0.06 调到 0.10，吸收宽窗在坡面上的系统性偏低（15° 坡约 3 cm）。
2. **逐柱量重写**（`terrain_analysis.cpp:168`）：
   - `landing`：贴地薄片 = 可落脚地面，`landing_level` 用片中心（抵消单格噪声）；
   - `vertical`：贴地片向上长过 0.12 m = 竖直结构（墙/杆/台阶立面/立柱）；
   - `elevated`：柱内存在片底高于参考地面 + 0.10 的片（抬高/悬空结构），**与是否同时有地面无关**
     （限高杆下有点的柱也要做净空判定）。
3. **抬高面区分可通行台面 / 悬空结构**（`terrain_analysis.cpp:213`）：
   抬高片标高与半径 5 格（0.25 m）内某个可落脚面标高一致（±0.05 m）→ `plateau`（台面/高台顶面，
   属于可通行区域，不按净空判障碍）；横梁/顶棚下方没有同层可落脚面 → 仍按净空判定。
4. **台阶立面识别**（`terrain_analysis.cpp:246`）：
   竖直结构顶面标高与邻域可落脚面一致 → `vert_step`（台阶/高台边沿的立面）。
   墙、立柱、限高杆立柱顶面没有同层可落脚面，不会被低侧闭环放大成一圈白。
5. **删除上一版判据 c（表面高差，只标高处一侧）**；新增**低处一侧闭环**判据 d
   （`terrain_analysis.cpp:331`）：
   对每个可落脚地面柱，半径内出现
   (i) 台阶立面（`vert_step`）顶面高出本落脚面 > `kStepLevelDiff`（半径 1 格），或
   (ii) 更高的可落脚面（台面/高台顶面，半径 4 格 = 0.2 m），
   → **标障碍在本柱（低处一侧）**。台阶边沿闭合只用低处一侧能看到的证据（立面点/低地侧地面），
   不依赖台面一侧是否有点；台面一侧不再被标。
   `kStepLevelDiff = 0.10 + 0.03 = 0.13 m`：可攀爬 10 cm 台阶不判障碍，攀爬不上的台阶/台沿稳定判障碍。
6. **悬空/抬高结构判定 b 保留**：净空（邻域同层 75% 分位聚合）< `robot_height` → 障碍；
   ≥ 且同层横向连续 → 可通行；孤立高片 → 障碍（细杆/稀疏立柱保护）。
7. 未知语义不变：无任何片的柱、或邻域无可靠地面参考的柱仍不写，2D 保持原值。

### Behavior preserved

- `analyze` 两个重载签名、返回值语义、`free_out` 语义；2D 三态回写与 2 帧滞回；建图/导航分支。
- 平地、坡道面、坡道↔台面接缝：0 误判（仿真见下）。
- 隧道顶/桌下（净空 ≥ robot_height）：可通行；细杆/长墙：仍判障碍。
- 可攀爬 10 cm 台阶：不判障碍（机器人能爬）。
- 限高杆 / 限高杆立柱：梁正下方 0 障碍，立柱仍判障碍。
- `robot_height`、`max_step_height`、`steep_threshold` 值不变。

### Behavior intentionally adjusted

- **`kernel_size` 3 → 7**：这是本次修复的核心参数（地面参考窗口必须大于横梁进深）。
  只影响地面参考场，不影响其它逻辑。
- **台阶/台沿白带从台面一侧移到低地一侧**：低地侧多 1~2 格（5~10 cm）白，台面一侧只剩含立面条点的
  1 格（几何固有）；不再出现"台面内侧一圈"。
- **台面顶面（净空 < robot_height 的抬高面）不再按净空判障碍**：20 cm 台阶台面顶面不再整片判障碍，
  只有边沿（低地侧 + 立面格）判障碍。
- **限高杆横梁**：从"受梁下地面点影响、时而判障碍"变为"只要净空够就整段可通行"。
- **墙脚/立柱周围不再被低侧闭环放大**（只认台阶立面）。
- **坡道侧边**：没有侧立面点时不再自动标白（旧判据 c 会顺带标出）；有侧立面点仍由判据 a/d 标出。

### Notes

- 新增常量均为函数内 `static constexpr`：`kGroundRefQuantile`(0.10)、`kStepLevelDiff`、
  `kPlateauRadius`(5)、`kPlateauTol`(0.05)、`kRingVerticalRadius`(1)、`kRingLevelRadius`(4)；
  删除 `kStepSearchRadius`/`kStepWitnessMin` 与 `surface` 数组。
- 每帧新增 3 个 O(n) 扫描：台面判定（抬高柱 × 11×11）、台阶立面（竖直柱 × 11×11）、
  低侧闭环（落脚柱 × 3×3 + 9×9），200×200 窗口量级仍为几 ms。

## Known issues / 风险

1. **3D 体素量化下限**：terrain 输入是 0.05 m 体素中心，净空只能按 5 cm 层取值（250 mm → 0.25）。
   实测净空若落在 0.225 层（真实 0.20~0.24 m 附近），会被判"钻不过去"。这是 3D 地图分辨率下限，
   不是判据可调的；若现场仍偶发，需要先确认实测净空与体素层对齐情况（或调 `robot_height`，但会
   牺牲安全余量）。
2. **坡道侧边**：坡道侧边如果没有侧立面点（只是悬空抬高边），本版不再自动标白；现场若坡道侧边
   需要白，靠侧立面点或坡道旁的地面高差（判据 d(ii)）覆盖，建议实车确认。
3. **极陡坡/陡坎的误标**：低侧闭环 (ii) 半径 4 格 = 0.2 m，若某坡面在 0.2 m 水平距离内高差 > 0.13 m
   （约 33°）会判障碍。场地 11°/15° 坡无此问题。
4. **台面一侧仍会有 1 格（5 cm）含立面点的格判障碍**：立面点落在台面侧体素时（几何上就是边沿），
   无法完全消除；这 1 格属"边沿"本身。
5. **仿真瞬态**：坡道面 1 帧 1 格（早期累积地图稀疏时的瞬态）；横梁/顶棚在极早期若干帧可能仍有
   零星翻转（已从 9 格降到 1 格）。
6. **编译未执行**：本记录只覆盖静态检查 + 离线判据验证；编译与实车验证待用户授权/测试。
